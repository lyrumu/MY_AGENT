- 解决问题要遵循“第一性原理”；涉及复杂后端要做“对抗性审查”；时刻注意代码规范性与维护性；不要污染系统环境
- terminal命令都要注释表明这是在做什么；除非必要 不使用真实浏览器
- 有不明确的需求必须先问我 禁止猜想
- 先读懂代码再修改具体文件
- 做前端UI优化时 尽量确保后端所有逻辑不变 确保项目后端功能不减少
- 终端命令涉及国外网络访问时，使用 `/bin/zsh -ic 'proxyon && <实际命令>'`
  proxyon 定义在 ~/.zshrc 中，需要交互式 zsh 加载
  开启代理和实际网络命令必须在同一次 shell 调用中执行，
  不要假设代理环境变量会跨工具调用保留。
- 本地用于诊断，测试等的服务进程在使用过后要及时关闭
- 应用 grilling skill 时，每轮问题必须用 `questionnaire` 工具收集答案，不要只输出 ❓/➡️ 文本：先发一小段文字说明本轮 frontier（可问的问题）、依赖关系和推荐理由，再用一次 `questionnaire` 调用提交本轮全部问题（多问题走 tab 栏）。
  - 每个问题的选项：推荐项置顶并标注「推荐」，再给 2~3 个真实备选，用 description 说明取舍；保留 allowOther 供用户自由输入。
  - prompt 中写明推荐答案本身，使「选推荐项」等价于 grilling 原本的「yes 接受推荐」。
  - 拿到结果后把自定义输入归一化为该题答案并继续下一轮；用户取消则停止提问，复述已确定的决策及其影响。
