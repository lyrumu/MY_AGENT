# 公众号文章打磨

围绕本篇文章的读者和目的，完成内容、配图与阅读体验。方法可复用，具体受众、结构、工具和样式按当次任务确定。

## 工作方式

1. 先读已有稿件、素材和用户反馈，明确文章主题、读者已有知识、阅读目的及交付位置。已知信息直接沿用；缺少会改变方向的信息才询问。编辑旧稿前查看当前版本，保留用户的后续修改。
2. 根据文章类型和用户意图，核对需要的事实，组织完整文稿及配图安排。提交前从读者视角集中打磨一遍，解决开头、结构、内容取舍和必要步骤，目标是让用户第一次看到的就是可以直接评阅的完整文章；不要用提纲或空泛示例代替成稿。具体判断可参考 [内容与读者复核](references/editorial-review.md)。
3. 默认先在对话中展示完整文稿，等待用户反馈或确认；根据反馈修订，获准进入编辑器后使用最终讨论好的文稿排版、配图并保存；仅排版或修样式时不擅自改写正文；对照并保留用户在线上的后续修改，按项目约定同步文稿。用户明确要求直接编辑或无需先看稿时按其要求执行；此前已经确认的文稿不重复要求确认。遇到关键信息不明或必须由用户处理的阻碍时询问或暂停。用到秀米、收藏、图库等素材时，读取 [编辑器与素材工作流](references/editor-workflow.md)，现场查看并按用途选择。
4. 操作前看准内容和位置，边做边留意结果；收到反馈时主动检查相关位置是否存在同类问题。完成后核对内容与呈现并保存；删改正文须在已授权范围内。已有本地 HTML 时可运行下方检查；在线编辑器直接检查页面，避免反复检查同一结果或制造额外流程。

## 内容取舍

- 从读者的具体痛点出发，让第一屏迅速说清文章价值；适合直接回答的问题就开门见山，不强塞虚构故事或冗长铺垫。标题与措辞可以有吸引力，但不得夸大产品能力或误导读者。
- 用具体、易懂的语言表达；解释深度取决于目标读者。同一信息不反复说，删除空泛铺垫、重复总结和不影响理解或行动的细枝末节。
- “详细”指读者需要的信息完整，“简洁”指表达没有冗余。某个限制或例外只有影响本篇读者的判断、操作结果或重要风险时才展开；不能因为追求短而删掉关键条件。
- 素材是候选信息，不是必写清单。先围绕本篇需求筛选；不要为了容纳一条素材，额外假设读者遇到了某种少见情形。
- 介绍产品时，把关键能力自然转化为读者能获得的具体好处，配合贴近读者的应用场景；区分亲测案例与可尝试的示例。确有助于选择时，依据可靠来源客观比较同类方案；采用易变化的数字时标明核查时间。
- 产品或教程文章先回答读者为什么需要、能用来做什么，再按需求给出可执行的安装或使用步骤；例子贴近实际且各有作用。该比较时用简短、可核实的对比帮助选择，不过度罗列参数、少见限制和无关背景。
- 涉及操作时，写清实际入口、动作与结果，符合本篇选定的工作方式；不沿用其他文章的产品、工具或技术路径。可变事实按需核对当前官方资料或实际界面，区分证据、推断与示例。
- 图片应帮助解释、提供证据或推进叙事，并适合读者的语言与知识背景。按内容选择截图、图库图片、图表或插图，不按数量凑图；示意图不能冒充真实操作结果。

## 排版与检查

- 从手机阅读效果判断段落长度、留白和图文关系；避免文字堆砌，根据内容灵活使用表格、分点等结构梳理关系，整合重复信息。结合编辑器现有模板、图片处理和文字效果建立清晰层级；按实际内容、外观和用途选择，不绑定收藏顺序或临时页面标识，也不为装饰牺牲可读性。
- 正文段落默认首行缩进两个汉字；标题、表格、代码块等按内容和版式处理。用加粗、下划线、斜体等突出重点，留意对齐、混排间隙、断行及溢出；用户另有指定时从其要求。
- 本地 HTML 已存在时，用标准库脚本做只读检查：

  ```sh
  # 检查本地 HTML 中的空图片、丢失的本地图片和未完成标记
  python3 <本 Skill 目录>/scripts/check_article.py /path/to/article.html
  ```

  脚本输出 JSON；退出码 1 表示发现确定的错误，2 表示输入或解析失败，0 仅表示未发现这些机械错误。提醒项须结合上下文判断。站点根路径可通过 `--asset-root` 指定。标记检查仅覆盖连续文本节点；远程或内嵌图片、CSS 背景图、事实和视觉效果不在验证范围。不要为运行脚本额外制造无用导出文件。
- 实际预览用于判断信息焦点、配图位置和阅读节奏。较复杂的文章或重大修改可由独立审阅者复核具体歧义、缺失与冗余；模拟反馈不冒称真人反馈。脚本、文字复核和编辑器保存均不能替代微信内的实际显示验证。

## 在使用中改进

修改本 Skill 前先判断反馈是可复用原则、特定条件下的方法，还是仅属本篇文章。只把可复用内容写入主文件或相应参考；具体产品、读者年龄、组件顺序和某篇的目录留在文章上下文中。遵守当前有效的修改授权。

更新时优先替换错误规则，避免不断叠加禁令。改动脚本运行 [脚本测试](scripts/test_check_article.py)；涉及写作行为时，从 [回归场景](references/regression-cases.md) 选择受影响的场景实际试写或演练，观察输出后再修正规则，不以“检查清单已勾选”代替结果。

这些步骤由使用 Skill 的代理执行；此包未安装自动运行钩子或宿主交付门禁。
